# سرخطی‌زن بورس تهران

ابزار خط‌فرمانی برای ارسال سفارش در لحظهٔ بازگشایی، با دقت زمانی میلی‌ثانیه‌ای.
با **ایزی‌تریدر مفید** و هر OMS دیگری که روی HTTP کار می‌کند کار می‌کند، و یک
مسیر جایگزین هم دارد که مستقیماً پنجرهٔ دسکتاپ ایزی‌تریدر را می‌راند.

> ⚠️ **پیش از استفاده بخوانید.** ارسال خودکار سفارش ممکن است با قوانین کارگزار
> یا مقررات سازمان بورس شما در تضاد باشد. مسئولیت دریافت مجوز از کارگزار و
> رعایت محدودیت‌های نرخ درخواست با خودتان است. این ابزار عمداً تعداد تلاش‌ها را
> کم و کنترل‌شده نگه می‌دارد و هیچ راهی برای دور زدن احراز هویت یا محدودیت‌های
> کارگزار ندارد. حالت پیش‌فرض **شبیه‌سازی** است و سفارش واقعی نمی‌فرستد.

## دقت از کجا می‌آید؟

«سرخطی» یعنی سفارش شما در همان میلی‌ثانیهٔ بازگشایی به صف برسد. سه منبع خطا
وجود دارد و برای هر سه راه‌حل داریم:

| منبع خطا | راه‌حل | دقت عملی |
|---|---|---|
| اختلاف ساعت شما با ساعت سرور | لبه‌یابی هدر `Date` سرور کارگزار + SNTP | ۵ تا ۱۵ میلی‌ثانیه |
| خطای `time.sleep` سیستم‌عامل | خواب تقریبی + حلقهٔ اشغال در ۲۰ms آخر | زیر ۱ میلی‌ثانیه |
| تأخیر شبکه و دست‌دادن TLS | اتصال و TLS از قبل، بایت‌های درخواست از پیش ساخته، `TCP_NODELAY`، پیش‌فرست به اندازهٔ نصف RTT | ۱۰ تا ۴۰ میلی‌ثانیه (وابسته به اینترنت شما) |

**لبه‌یابی هدر `Date`** نکتهٔ اصلی است: این هدر فقط ثانیه را می‌دهد، ولی اگر
پشت‌سر‌هم درخواست بزنیم و لحظه‌ای را پیدا کنیم که مقدارش یک واحد می‌پرد، مرز
ثانیهٔ *خودِ سرور کارگزار* را با خطای چند میلی‌ثانیه به دست آورده‌ایم — و مرجعِ
واقعیِ پذیرش سفارش هم همان ساعت است، نه ساعت اتمی جهانی.

اندازه‌گیری واقعی روی یک سرور عمومی: عدم‌قطعیت **۱۲ میلی‌ثانیه** در ۱٫۳ ثانیه
نمونه‌برداری. خطای زمان‌بندی حلقهٔ شلیک در تست‌ها زیر **۱ میلی‌ثانیه** است.

## نصب

```bash
git clone <این مخزن> && cd marketing-automation
pip install -r requirements.txt        # فقط PyYAML؛ بقیه کتابخانهٔ استاندارد است
cp config.example.yaml config.yaml
```

## پیکربندی

همهٔ تنظیمات در `config.yaml` است (نمونهٔ کامل با توضیح: `config.example.yaml`).
سه بخش را باید خودتان پر کنید:

**۱. سفارش و کنترل ریسک**

```yaml
order:
  symbol: "فولاد"
  isin: "IRO1FOLD0001"
  side: buy
  quantity: 1000
  price_mode: upper_band        # سقف دامنهٔ روز؛ یا lower_band / limit
  reference_price: 5430         # قیمت پایانی دیروز به ریال
risk:
  band_pct: 3.0                 # دامنهٔ نوسان همان نماد
  max_order_value: 1000000000   # سقف ارزش سفارش به ریال
  allowed_symbols: ["فولاد"]    # فهرست سفید — پرش کنید
```

قیمت سقف/کف از روی قیمت پایانی دیروز حساب می‌شود و **همیشه به سمت داخل دامنه**
گرد می‌شود تا سفارش به‌خاطر یک ریال اختلاف رد نشود.

**۲. اتصال به ایزی‌تریدر**

شکل درخواست ثبت سفارش ایزی‌تریدر عمومی نیست و کارگزار هرازگاهی تغییرش می‌دهد،
پس این بخش «قالب‌محور» است: یک‌بار درخواست واقعی را استخراج کنید و در تنظیمات
بگذارید.

1. در مرورگر وارد ایزی‌تریدر شوید، `F12` → تب **Network**.
2. یک سفارش آزمایشی (مثلاً با قیمتی دور از بازار که پر نشود) ثبت کنید.
3. درخواست ثبت سفارش را پیدا کنید و از آن بردارید: مسیر (`order_path`)، هدرها و
   بدنهٔ JSON.
4. بدنه را در `payload_template` بگذارید و مقادیر متغیر را با جای‌نگهدار
   `{isin}` `{symbol}` `{price}` `{quantity}` `{side}` `{validity}` جایگزین کنید.

```yaml
broker:
  name: easytrader
  settings:
    base_url: "https://api.emofid.com"
    order_path: "/easy/api/OmsOrder/Post"
    token_env: SARKHATI_TOKEN
    payload_template:
      isin: "{isin}"
      quantity: "{quantity}"
      price: "{price}"
      side: "{side}"
```

توکن **هرگز داخل فایل نوشته نمی‌شود**؛ از متغیر محیطی خوانده می‌شود:

```bash
export SARKHATI_TOKEN='...'
```

**۳. حالت دسکتاپ (اگر به API دسترسی ندارید)**

فرم سفارش را خودتان در ایزی‌تریدر پر می‌کنید، برنامه فقط سرِ ساعت روی دکمهٔ
«ارسال» کلیک می‌کند:

```yaml
broker:
  name: desktop
  settings: { mode: click, x: 1180, y: 640, window_title: EasyTrader }
```

نیازمند `pip install pyautogui pygetwindow`. در این حالت `retries: 0` بگذارید —
از روی رابط گرافیکی نمی‌شود فهمید سفارش پذیرفته شده یا نه و تلاش دوم یعنی خطر
سفارش تکراری.

## استفاده

```bash
python -m sarkhati sync         # اختلاف ساعت شما با مرجع
python -m sarkhati calibrate    # تأخیر شبکه تا کارگزار و پیش‌فرست پیشنهادی
python -m sarkhati bands --reference 5430   # کف و سقف دامنهٔ نوسان
python -m sarkhati check        # اعتبارسنجی و پیش‌نمایش سفارش
python -m sarkhati run          # اجرای کامل در حالت شبیه‌سازی (بدون ارسال)
python -m sarkhati run --now    # همان، ولی فوری — برای تست
python -m sarkhati run --live   # ارسال واقعی (با تأیید دستی)
```

خروجی نمونه:

```
تلاش 1: خطای زمانی    +0.4ms | پاسخ   31.2ms | پذیرفته — سفارش پذیرفته شد (HTTP 200)
```

**روال پیشنهادی شب قبل:** `check` بزنید، بعد `calibrate` تا پیش‌فرست را ببینید،
و یک‌بار `run` (شبیه‌سازی) بگیرید. صبح فقط `run --live` را چند دقیقه قبل از
بازگشایی اجرا کنید؛ برنامه خودش ۴۵ ثانیه مانده به هدف اتصال‌ها را گرم می‌کند،
ساعت را دوباره همگام می‌کند و سرِ ثانیه شلیک می‌کند.

## نسخهٔ ویندوز (بدون نصب)

پوشهٔ `windows/` یک برنامهٔ تک‌فایلی برای ویندوز است: اجرا که شد، رابط کاربری
را در مرورگر باز می‌کند. نه نصب می‌خواهد نه وابستگی. علاوه بر ارسال از طریق
API، حالت «کلیک روی ایزی‌تریدر دسکتاپ» هم دارد.

```bash
cd windows && GOOS=windows GOARCH=amd64 go build -ldflags "-s -w" -o sarkhati.exe .
```

جزئیات در `windows/README.md`.

## نسخهٔ اندروید

پوشهٔ `android/` یک اپ بومی اندروید با همین منطق است (همگام‌سازی ساعت، کنترل
ریسک، انتظار دقیق و ارسال سفارش). برای گرفتن فایل APK دو راه هست:

- **گیت‌هاب اکشنز:** مخزن را پوش کنید؛ ورک‌فلو `.github/workflows/android.yml`
  خودکار بیلد می‌گیرد و APK را در بخش Artifacts می‌گذارد.
- **Android Studio:** پوشهٔ `android/` را باز کنید و `./gradlew assembleDebug`.

جزئیات در `android/README.md`.

## محافظ‌ها

- حالت پیش‌فرض شبیه‌سازی است؛ `--live` لازم است و تأیید دستی می‌خواهد.
- قبل از هر ارسال: کنترل دامنهٔ نوسان، گام قیمت، سقف حجم، سقف ارزش سفارش و
  فهرست سفید نمادها.
- اگر عدم‌قطعیت ساعت از `max_uncertainty_ms` بیشتر باشد، ارسال زنده **متوقف**
  می‌شود؛ شلیک با ساعت نامطمئن بدتر از نزدن است.
- تلاش‌های پشتیبان محدود و با فاصله‌اند و با اولین پذیرش متوقف می‌شوند.

## ساختار

| فایل | کار |
|---|---|
| `sarkhati/timesync.py` | همگام‌سازی ساعت (SNTP و لبه‌یابی هدر `Date`) |
| `sarkhati/scheduler.py` | انتظار دقیق و برنامهٔ شلیک و تلاش‌های پشتیبان |
| `sarkhati/risk.py` | دامنهٔ نوسان، گام قیمت و کنترل‌های ایمنی |
| `sarkhati/brokers/easytrader.py` | ارسال HTTP با اتصال از پیش گرم‌شده |
| `sarkhati/brokers/desktop.py` | راندن پنجرهٔ ایزی‌تریدر دسکتاپ |
| `sarkhati/runner.py` | جریان کامل: اعتبارسنجی ← همگام‌سازی ← گرم‌کردن ← شلیک |
| `sarkhati/cli.py` | خط فرمان |

## محدودیت‌های صادقانه

- `order_path` و `payload_template` پیش‌فرض **حدسی‌اند** و تأیید نشده‌اند؛ بدون
  جایگزین کردن با درخواست واقعی خودتان، ارسال زنده کار نمی‌کند.
- کف دقت را اینترنت شما تعیین می‌کند: با ۸۰ میلی‌ثانیه پینگ، دقت بهتر از
  ۴۰ میلی‌ثانیه ممکن نیست. سرور مجازی داخل ایران به کارگزار نزدیک‌تر است.
- برای صف‌های پرتقاضا، سرعت شما فقط یکی از عوامل است؛ اولویت صف را کارگزار و
  هستهٔ معاملات تعیین می‌کنند.
