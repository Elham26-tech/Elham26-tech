# سرخطی‌زن

ابزار محلی ارسال سفارش در لحظهٔ بازگشایی بازار. سرور روی `127.0.0.1:9117` بالا می‌آید و
رابط کاربری فارسی/RTL دارد. هیچ وابستگی بیرونی ندارد (فقط Node.js نسخهٔ ۱۸ به بالا).

```bash
cd sarkhati
npm start        # http://127.0.0.1:9117
npm test         # تست‌ها
```

> ابزار فقط روی حساب کارگزاری خودتان و با توکن خودتان کار می‌کند. نرخ ارسال را
> متناسب با قواعد کارگزاری‌تان تنظیم کنید.

## سه باگی که در این نسخه رفع شده

### ۱. ماندن حافظهٔ اجرای قبلی بعد از باز کردن دوبارهٔ برنامه

داده‌ها به سه لایهٔ جدا تقسیم شده‌اند (`lib/store.js`):

| لایه | فایل | عمر |
|---|---|---|
| تنظیمات کاربر | `data/settings.json` | ماندگار |
| وضعیت جلسه (مسلح بودن، تلاش‌ها، گزارش) | `data/session.json` | فقط همان روز معاملاتی |
| قالب‌های یادگرفته‌شده از کارگزاری | `data/learned.json` | ماندگار، با دکمهٔ فراموشی |

وضعیت جلسه با کلید روز معاملاتی ذخیره می‌شود؛ اگر روزِ ذخیره‌شده با امروز فرق کند،
موقع بالا آمدن دور ریخته می‌شود. حتی در همان روز هم «مسلح بودن» به اجرای بعدی به ارث
نمی‌رسد تا بعد از ری‌استارت، برنامه خودبه‌خود شلیک نکند. رابط کاربری چیزی در
`localStorage` نگه نمی‌دارد و تنها منبع حقیقت، سرور است. دو دکمهٔ «پاک‌کردن حافظهٔ جلسه»
و «فراموش‌کردن یادگرفته‌ها» هم در بخش تنظیمات پیشرفته هست.

### ۲. خطای `HTTP 400 — Order.Side ... سفارش معتبر نمی‌باشد`

این خطا ربطی به بسته بودن بازار نداشت؛ خطای اعتبارسنجی خود کارگزاری بود، یعنی مقدار
فیلد `Side` آن چیزی نبود که سرور انتظار داشت. رفع در `lib/order.js`:

- ورودی کاربر (`خرید`/`buy`/`1`/…) اول به `buy`/`sell` یکدست می‌شود.
- چهار قالب رایج پشتیبانی می‌شود: `1|2`، `Buy|Sell`، `buy|sell`، `BUY|SELL`.
- در حالت **خودکار** اگر پاسخ ۴۰۰ دربارهٔ همین فیلد باشد، قالب بعدی بلافاصله امتحان
  می‌شود و قالبی که پذیرفته شد در `learned.json` حفظ می‌شود تا دفعهٔ بعد اولین گزینه باشد.
- هیچ سفارشی با `Side` خالی یا تعداد/قیمت صفر اصلاً ارسال نمی‌شود؛ دکمهٔ «بررسی»
  همین اعتبارسنجی را بدون ارسال انجام می‌دهد و بدنهٔ دقیق درخواست را نشان می‌دهد.

### ۳. شروع نشدن قبل از بازگشایی

شلیک دیگر روی خودِ ساعت هدف شروع نمی‌شود:

```
لحظهٔ شروع شلیک = ساعت هدف − preArmSeconds + اختلاف ساعت سرور
```

`preArmSeconds` پیش‌فرض ۶۰ ثانیه است (قابل تغییر تا ۶۰۰)، پس اگر کارگزاری یک دقیقه
زودتر باز کند، تلاش‌ها از قبل در جریان‌اند و اولین سفارشِ پذیرفته‌شده کار را تمام
می‌کند. دکمهٔ «همگام‌سازی ساعت» اختلاف ساعت سیستم با سرور کارگزاری را از هدر `Date`
حساب می‌کند (با تصحیح نصف زمان رفت‌وبرگشت) و در همین محاسبه اعمال می‌شود.

## ساختار

```
sarkhati/
├─ server.js        سرور HTTP و API
├─ lib/store.js     سه لایهٔ داده و کلیدِ روز معاملاتی   (باگ ۱)
├─ lib/order.js     ساخت و اعتبارسنجی سفارش، قالب‌های Side (باگ ۲)
├─ lib/engine.js    ساعت، pre-arm، حلقهٔ شلیک، یادگیری     (باگ ۳)
├─ public/          رابط کاربری RTL
└─ test/run.js      تست‌ها
```

## نکته‌ها

- ساعت هدف با **ساعت محلی همان کامپیوتری** که سرور روی آن اجراست حساب می‌شود؛
  منطقهٔ زمانی سیستم را روی `Asia/Tehran` بگذارید.
- `data/` در گیت نادیده گرفته شده تا توکن کارگزاری هرگز commit نشود.
