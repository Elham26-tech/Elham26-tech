# سرخطی‌زن

ابزار محلیِ ارسال سفارش در لحظهٔ بازگشایی بازار. خروجی یک فایل `sarkhati.exe`
است: **بدون نصب، بدون Node** — دوبار کلیک می‌کنید، پنجرهٔ مشکی باز می‌ماند و
صفحهٔ کنترل خودش در مرورگر باز می‌شود. (پنجرهٔ مشکی را نبندید و داخلش Ctrl+C
نزنید.) فقط کروم یا اِجِ خودِ ویندوز لازم است.

## روش کار

```
۱  «باز کردن ایزی تریدر»  →  کروم با صفحهٔ کارگزاری باز می‌شود
۲  خودتان لاگین می‌کنید و یک بار دستی خرید/فروش می‌زنید
۳  برنامه همان سفارش واقعی را یاد می‌گیرد  ✓
۴  نماد را جست‌وجو می‌کنید؛ سقف/کف و تعداد مجاز از کارگزاری می‌آید
۵  ساعت هدف را می‌دهید و «مسلح کردن» را می‌زنید
```

نام کاربری و رمز کارگزاری **هیچ‌وقت وارد این برنامه نمی‌شود**؛ لاگین داخل خودِ
پنجرهٔ کروم انجام می‌شود و نشست فقط در پروفایل کروم می‌ماند.

## سقف و کف: از کارگزاری، نه از تخمین

مرجع واقعیِ «چقدر مجازی بفرستی» خودِ کارگزار است، نه دامنهٔ نوسانی که از قیمت
دیروز حساب شود — و تعداد مجاز هر سفارش اصلاً در دادهٔ تابلو نیست. پس:

- وقتی داخل ایزی‌تریدر نمادی را باز می‌کنید، برنامه **مسیر اطلاعات نماد** را
  یاد می‌گیرد (`lib/endpoint.js`): نام پارامتری که کد نماد در آن است، چه در
  نشانی باشد، چه در بدنهٔ JSON، چه داخل متن یک فیلد مثل پرس‌وجوی GraphQL.
- بعد همان درخواست با کد نماد انتخابی، **از داخل خود صفحهٔ کارگزاری** تکرار
  می‌شود، پس کوکی و توکن نشست همان‌هایی‌اند که مرورگر می‌فرستد.
- سقف/کف/تیک/تعداد مجاز با الگوی نام از پاسخ بیرون کشیده می‌شود
  (`lib/limits.js`)، چون نام فیلدها بین کارگزاری‌ها فرق دارد.
- اگر کارگزاری چیزی نداد، تخمین ±۵٪ از قیمت دیروز استفاده و صریحاً **«تخمینی»**
  برچسب می‌خورد تا با عدد رسمی اشتباه نشود.

TSETMC فقط برای **فهرست نام نمادها** به کار می‌رود: کل بازار یک‌بار گرفته و
ذخیره می‌شود، بعد جست‌وجو محلی و آنی انجام می‌گیرد — بدون رفت‌وبرگشت شبکه به
ازای هر حرف.

## رفتارهای مهم

**حافظه** — سه لایهٔ جدا: تنظیمات (ماندگار)، وضعیت جلسه (فقط همان روز
معاملاتی)، و آنچه از کارگزاری یاد گرفته شده. وضعیت جلسه با کلید روز ذخیره
می‌شود و روز بعد دور ریخته می‌شود؛ «مسلح بودن» هم هرگز از اجرای قبلی به ارث
نمی‌رسد تا برنامه بعد از ری‌استارت خودبه‌خود شلیک نکند.

**قالب سفارش** — هیچ فیلدی حدس زده نمی‌شود. همان درخواست واقعیِ خودتان ضبط
می‌شود (فقط وقتی کارگزاری با ۲xx پذیرفته باشد) و موقع تکرار فقط
تعداد/قیمت/نماد جایگزین می‌شوند؛ مقدار `Side` عیناً همان می‌ماند که پذیرفته
شده بود. درخواست‌های آمار و تبلیغات (مثل گوگل آنالیتیکس) هرگز سفارش حساب
نمی‌شوند — تشخیص بر اساس محتوای بدنه است، نه آدرس.

**شروع زودتر از بازگشایی**

```
لحظهٔ شروع شلیک = ساعت هدف − preArmSeconds + اختلاف ساعت سرور
```

پیش‌فرض ۶۰ ثانیه، پس اگر کارگزاری یک دقیقه زودتر باز کند تلاش‌ها از قبل در
جریان‌اند. صفحه شمارش معکوس زنده نشان می‌دهد و حین شلیک، تعداد تلاش‌ها را.

## ساختار

```
sarkhati/
├─ server.js        سرور محلی و API
├─ lib/ws.js        کلاینت وب‌سوکت کمینه، بدون وابستگی
├─ lib/browser.js   باز کردن کروم و پروتکل DevTools
├─ lib/recipe.js    یادگیری و بازسازی سفارش
├─ lib/endpoint.js  یادگیری مسیر اطلاعات نماد از کارگزاری
├─ lib/limits.js    سقف/کف و تعداد مجاز از پاسخ کارگزاری
├─ lib/tsetmc.js    فهرست کل بازار برای جست‌وجوی محلی
├─ lib/store.js     سه لایهٔ داده و کلید روز معاملاتی
├─ lib/engine.js    ساعت، شروع زودهنگام، حلقهٔ شلیک
├─ public/          صفحهٔ کنترل دوستونی (فارسی/RTL)
└─ test/            run.js (۴۰ تست) و e2e.js (تمرین با کروم واقعی)
```

## اجرا از روی سورس

```bash
node server.js       # http://127.0.0.1:9117
npm test             # ۴۰ تست واحد
npm run test:e2e     # کارگزاری قلابی + کروم واقعی
```

ساخت فایل اجرایی: `BUILD.md`

## نکته‌ها

- ساعت هدف با ساعت محلی همان کامپیوتر حساب می‌شود؛ منطقهٔ زمانی ویندوز را روی
  `Asia/Tehran` بگذارید.
- پاسخ `HTTP 5xx` از کارگزاری یعنی ایراد سمت آن‌هاست، نه سفارش شما — معمولاً
  بیرون از ساعت معاملات.
- نرخ ارسال را متناسب با قواعد کارگزاری خودتان تنظیم کنید.
